# GoldAgent 产品迭代记录：从功能集合到可追溯研究流程

开始日期：2026-10-20。本文描述实际代码改造、验证证据和剩余边界，不把路线图等同于已完成功能。

## 一、产品判断与落地顺序

原有产品具备行情、新闻、持仓、预测、回测、知识库和 Agent，但模块之间缺少衔接。用户得到长篇回答后，不容易核查、保存和再次使用；部分指标的计算口径也存在偏差。

本轮顺序是：**先修可信度，再补体验，再连研究资产**。不以增加 Agent 数量作为优化目标，而是加强现有单 Agent 的上下文、工具执行和结果管理。

```text
今日市场 / 新闻 / 个人资料
          ↓ 发起研究（可编辑问题）
Agent 动态选工具 → 来源核验 / 金融护栏
          ↓
研究任务记录 → 证据详情 → 保存报告 / 下载 / 重新研究
```

## 二、先解决已验证的问题

| 问题与原因 | 实际改造 | 用户效果与验证方式 |
|---|---|---|
| REST 带 Token，但聊天使用独立 fetch，下载使用普通链接 | 统一认证 fetch；并发刷新合并；认证下载；失效 Token 不退回 Demo；账户切换清缓存 | 聊天、报告与其他页面使用同一身份。测试覆盖刷新竞争、旧账户刷新覆盖风险、跨用户研究及报告拒绝访问 |
| 历史消息 reducer 不断追加 SystemMessage，新旧持仓和偏好并存 | 每轮重建唯一系统上下文；API 从所属用户会话加载已提交历史；当前资料替换旧资料 | 保留多轮对话，同时使用最新持仓偏好。回归测试确认旧偏好消失、新偏好存在、历史问题仍保留 |
| 回测收益曲线与逐笔交易独立计算，成本和数量对不上 | 用现金、持仓、成交、手续费的同一账本生成曲线和指标；前日收盘信号在次日开盘执行 | 逐笔费用之和等于汇总费用；买卖数量守恒；净值可由现金和持仓重建；实现与浮动盈亏可对账 |
| 选择多周期预测，评估仍默认一步；页面与工具口径不同 | 共用 evaluated_forecast；评估绑定 horizon、lookback、样本量、目标日期；加入价格不变基准 MAE/RMSE | 用户能知道指标评估的对象，避免把一步指标理解成未来多日概率 |
| 中文本地 Hash 不是语义模型，零相关文档也进入 top-k | 中文二元词组与英文词项召回；相关性门槛；生产 PostgreSQL 中执行向量距离候选检索；兼容性检查；PDF 页码与分块来源 | 无关查询返回资料不足；不把 Hash 碰撞当语义证据。文档删除、分块隔离、相关/无关检索均有测试 |
| 报告只保存固定 note | 从已完成 Run 保存问题、回答、工具输出、来源、预算和核验记录；支持预览、下载；未选 Run 则保存真实行情快照 | 一份报告可以独立解释研究依据，不额外调用模型编造报告；拒绝跨用户及未完成研究保存 |
| SSE 只等队列，任务完成后可能再等十秒 | 同时等待队列事件和任务终态；取消传播；保留阶段和工具事实事件 | 离线端到端 API 测试要求快速任务在 3 秒内结束，不再承担固定十秒尾部等待；这不是线上模型延迟 SLA |
| 达到步数上限仍标记 completed；重启后回测可能一直运行 | 保留 max_steps 终态；重启将中断的对话/回测标为失败 | 不把未完成研究伪装成成功，用户可看到失败并重新发起 |

回测边界：AU0 为连续参考行情，不是可直接交易的合约；未建模保证金、换月、实物金价差、冲击成本和流动性。期末持仓按收盘估值、不强制清仓；买入持有基准同样计入入场手续费并保留期末仓位。旧回测记录不静默重算，需要重新运行。

预测边界：日线步数不是自然日；滚动样本存在重叠，历史命中率不是未来概率；未提供经过样本外校准的置信区间。

## 三、体验层优化

- **首页从裸数字转向任务入口**：市场变化、中文趋势、已有持仓的参考浮盈亏、今日研究和更新持仓入口。60 秒刷新，保留行情时间与陈旧数据提示。AU0 估值明确不是具体黄金产品的可成交报价。
- **降低首次使用成本**：今日简报、持仓风险、事件解读、研报问答四类任务模板；先填入问题供用户编辑，不自动产生付费模型调用。
- **对话阅读空间可控**：会话历史默认折叠；执行详情可折叠；回答区域自适应；接近底部时跟随滚动，向上阅读不强制拉回。
- **给等待与失败以操作出口**：停止、编辑上个问题重试、复制、明确终态；有帮助/需改进反馈写入对应 Run；研究完成后一键保存报告。
- **预测/回测可找回**：刷新后从后端历史记录恢复；预测路径对比价格不变基准；回测展示净值、基准与回撤曲线，展示当前参数、费率和评估说明。
- **新闻可直接成为研究起点**：600ms 搜索防抖、同标题去重、摘要 Markdown/HTML 清洗、刷新状态；对 72 小时外的 14 天补充内容单独标注；一键带入标题、来源、时间、URL，仍需模型核查。
- **移动端不再丢入口**：四个常用导航加“更多”，抽屉展示完整功能；聊天输入区避开底部导航。
- **知识证据可定位**：检索展示文件名、页码、分块；提供所属用户分块读取接口；可带入指定文档发起研究。

## 四、Agent 工程优化亮点

1. **上下文分层**：系统策略、会话历史、当前用户资料分别构建，避免持久化旧系统提示重复进入下一轮。当前尚未实现跨会话的可编辑长期记忆管理器。
2. **有预算的研究模式**：快速模式最多 4 次模型响应、单次最多 1600 输出 Token、总超时不超过 90 秒；深入模式服从配置中的上限。记录实际模型、调用数、用量、耗时和预算，不虚构人民币成本。供应商未返回用量时计数可能为零。
3. **只读工具限并发**：已知只读工具每批最多 3 个并发，输出仍按调用顺序交还模型；未知扩展串行。相同工具、相同参数在同一 Run 的注册表内合并请求，不建立跨用户私有数据缓存。
4. **受控证据结构**：evidence 带 schema_version、citations、snapshots、limitations。来源来自实际工具输出，失败和陈旧状态保留；界面不执行模型生成的代码。
5. **研究资产闭环**：Run 关联会话、问题、工具记录和报告；任务页可找回结果、错误和原始证据，并编辑问题重新研究；反馈保留在 Run，方便后续评测。
6. **可解释的部署健康**：/ready 区分本地依赖与配置，不再用 market_provider=true 暗示外部数据源已连通；未就绪返回 503，不通过健康检查调用付费模型。

当前依然是“阶段事件 + 核验后的最终回答分段发送”，不是模型生成过程的逐 Token 流。金融核验也不是事实真实性的形式化证明，不能代替来源交叉检查。

## 六、如何在面试中说明价值

> 我没有只增加聊天入口或堆叠多个 Agent，而是从一次完整的黄金研究任务出发，识别认证、上下文新鲜度、计算口径和结果留存的问题。随后把确定性计算、来源证据、任务记录和报告串起来，并用资金守恒、跨用户拒绝访问、无关文档拒绝召回等回归测试验证。产品层加入研究模板、可中断对话、图表与历史记录，让用户不必反复复制信息。

可以量化的证据是对账断言、检索拒绝用例、尾部延迟回归、构建和测试结果；没有线上数据支撑的留存率、准确率提升或成本下降百分比，不应写进简历。

## 八、2026-10-22：模块切换不再中断对话

- 原因：聊天组件卸载时主动 abort SSE，消息、工具状态也只在组件内保存。
- 改造：将请求执行、AbortController、消息、会话、进度和证据放入标签页级 Zustand 运行时；页面只订阅与展示，不负责请求存活期。
- 效果：同一标签页内切换新闻、持仓等模块后继续执行，返回对话保留进度或已完成结果；全站“Agent 对话”导航和运行会话显示旋转图标，结束后移除。
- 取消边界：用户点击停止、退出或切换账户时仍取消并清空；增加 generation 防护，旧请求的迟到回调不能覆盖新账户数据。
- 验证：新增组件卸载后继续接收结果、主动停止、账户切换隔离三项单测；浏览器测试检查“发送 → 离开模块 → 运行图标 → 返回 → 完成”，请求仅发送一次。
- 边界：这是同一浏览器标签页中的后台运行，不是服务端持久化队列；刷新、关闭标签页或断网仍可能中断，已有最终结果可从任务记录找回。

## 九、2026-10-22：深入研究的延迟优化

### 观察与判断

本地一条旧版深入研究记录约 105 秒，3 次模型调用、4 次工具调用，累计输入约 5.7 万 Token；其中新闻工具约 7 秒。它是单次样本，不是延迟分位数，不能仅通过缩短工具超时就认定解决了整体等待。

### 实际改造

1. **分开规划与深度综合**：默认 `final_only`。采集阶段用 MiMo 的 `thinking.type=disabled` 选择工具，最后综合使用 `enabled`，仍使用原来的 `mimo-v2.6-pro`，不是偷换快速模型或完全关闭深度分析。
2. **消除不必要确认往返**：模型可在最后一批工具中同时给出 `complete_research` 控制信号；系统等待该批真实工具结果后直接综合，无需再发一遍完整上下文只为确认“资料够了”。复杂依赖仍可多轮采集，不硬编码所有问题调用相同工具。
3. **控制送入模型的输入量**：新闻摘要保留短摘要、来源、URL、时间；长行情和回测曲线抽样，交易保留末段，指标和账本不重算；明确标注省略范围。原始输出仍完整保存在 Run，不把抽样数据伪装成连续序列。会话历史设置字符预算，最新用户问题完整保留。
4. **请求与协议优化**：一个 Run 复用 HTTP 连接池，结束或取消时关闭；使用 MiMo 文档中的 `max_completion_tokens`，预算包含可见输出与推理；保留模型多轮工具调用需要的私有 reasoning_content，但不显示到 UI、回答、事件或公共报告。
5. **限制重复与保护质量**：全批相同参数重复调用时进入综合；预留最终综合轮数；达到输出预算或被截断时保留 incomplete，而不是标记成功。金融护栏、来源核验和工具错误说明仍保留。
6. **可测量而非只改提示词**：每次请求记录规划/综合阶段、耗时、输入字符数、结束原因、推理 Token 和缓存 Token 数；记录原始与模型视图字符数，方便后续对比真实任务。

### 配置与取舍

`config.yaml` 的 `agent` 配置新增：

```yaml
deep_reasoning_strategy: "final_only" # 优先减少重复思考；every_round 恢复逐轮模式
planning_max_tokens: 1024            # 仅限制轻量规划响应
max_tokens: 4096                     # 最终综合的总生成预算，含推理
```

`src/settings.py` 提供相同默认值。最终模型、供应商和 API Key 不变，不自动改成有不同定价的 UltraSpeed 型号。

一条本地历史样本的工具视图从 12,546 字符缩减到 7,819 字符，减少约 37.7%；这是同一份结果在本地计算的输入缩减，不是线上总耗时改善百分比。可并行采集的测试场景验证只需“规划 → 工具 → 综合”两次模型请求；未提供结束控制信号时仍兼容 READY 兜底，可能需要额外一次轻量确认。

本轮不展示模型隐藏推理，不把核验前草稿冒充最终回答，也不宣称已实现逐 Token 最终答案流。实际速度仍取决于提供方排队、生成吞吐、任务依赖和最终回答长度；真实服务延迟需在同等任务与预算下持续评估。

协议依据：[小米 MiMo Chat Completions 官方文档](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)。文档明确了 thinking 开关、总生成预算和 reasoning_content 的回传约定。未为兼容接口臆造 reasoning_effort 或未经文档支持的思考预算参数。

### 验证

- 后端完整测试：43 passed；包含两阶段调度、采集完成信号、预算预留、截断终态、上下文压缩、私有推理回传和连接池复用。
- 前端类型检查通过，10 项单测通过；模块切换与完整业务链路继续由浏览器回归覆盖。
- 本地样本压缩测量不调用外部模型；不将真实会话或持仓发往额外评测服务，不虚构“比旧版快多少秒”。
- 最终生产镜像的 5 项 Edge E2E 通过，含跨模块持续运行与导航/会话标识；真实 Docker 冒烟通过。
- 另外进行了两次受控 MiMo 真实接口联调（共 4 次模型请求），均只使用“假设价格500元/克、上涨1%为505元/克”的合成工具，没有数据库读取、真实个人资料或外部新闻。相同模型、每轮2048生成预算：every_round 单次7.74秒、final_only 单次4.25秒，均 completed、2次请求。输出长度与推理 Token 不同，这是连通性与单次速度观察，不是严格统计基准，不能推广为所有任务固定提速比例或 SLA。

## 十、历史行情周期兼容修复

晨报任务失败的实际原因是模型传入 `period=1mo`，旧参数正则拒绝该月份写法，并不是新闻或行情源中断。统一 API 与工具的周期语义，支持日、周、自然月、年；兼容 `1m` 为一个月，`max` 为全部可用历史，不把月份误当分钟。

同时修复旧数据层只筛选年份、忽略月份/周/日的问题。按最后一条已完成日线向前计算日历窗口，限制结果条数另由 limit 控制；返回的实际起止时间与筛选结果一致，不伪造新数据。界面来源时间仍需保留以便判断新鲜度。

回归覆盖模型实际传参 `{market: CN, period: 1mo, limit: 30}`、周期别名、非法参数拒绝，以及真实窗口和元数据的一致性。

## 12. 从开发诊断界面到用户研究界面

- 核查范围：仪表盘、市场分析、Agent 对话、预测、回测、持仓、新闻、报告、知识库、任务记录、设置与登录页。

- 调整：以白名单方式展示研究步骤、完成状态、行情来源、获取时间、新闻发布时间与文档页码；移除原始 JSON、文档分块编号、回测任务编号和内部存储配置。未知状态、趋势与指标不再直接展示字段原文。
- 错误处理：按登录、权限、输入格式、限流、超时等情况给出中英文提示和下一步；后台诊断仍保留在内部记录，不拼入最终回答。工具执行失败和资料不足仍明确提示，不伪装为成功。

- 边界：这是用户展示与错误信息治理，不等同于完整的生产安全审计；结构化内部记录与权限控制仍由后端负责。
