## 二、针对发现的问题进行了什么优化

| 首测问题 | 改动 | 目的与验证 |
|---|---|---|
| 新闻只有域名，没有可核查链接 | 系统提示要求 URL / 来源 / 发布时间；若完全遗漏链接，后处理仅从本次成功工具结果补最多 3 条检索资料 | 不额外请求模型，不编造引用或发布时间；明确附录不表示每条资料支持所有结论 |
| 常识题查询无关知识库、回测额外取现价 | 明确“只查询完成当前问题必需的资料”，细化工具职责说明 | 仍由模型自主选工具，不增加按关键词强制路由；RSI 解释、回测题同题复测通过 |
| 缺持仓仍展开一整份市场报告 | 缺必要信息时先澄清，不顺带查询市场或预测 | 同题只用一轮回答，提示补充克数与平均成本 |
| 用户给定 650 却又计算 525 情景 | 明确当轮显式价格/持仓优先于保存资料，保存资料优先于旧历史；已给价格不擅自查另一价格 | 同题只调用一次持仓工具，返回浮盈 1000，不再附加另一价格情景 |
| 简单安全拒绝耗尽生成预算 | quick 阶段复用已有 MiMo thinking 开关并关闭额外思考；限制无关展开，最后一步可仅综合已有证据 | 不提高输出 Token 上限；deep 综合仍保留思考，截断状态检查仍在 |
| 浮盈被说成已实现收益 | 提示词明确区别；工具结果增加 `pnl_type=unrealized`、`realized_pnl_available=false` | 保留原有 PnL 数值；同题回答区分未实现收益，不伪造卖出记录 |
| MAE 被当成未来正负价格区间 | 提示词与工具说明解释历史误差；工具结果标注没有统计置信区间 | 预测仍用正式计算服务，不将误差包装成未来上下界 |
| 知识库引用省略文件标识 | 要求完整文件名、已有页码，不虚构 | 最后同题包含真实文件名和页码，通过原来的文档引用合同 |
| 安全拒绝插入无证据“近期波幅” | 补充常识/拒绝不夹带未经查询的当前数字，不从风险偏好推出完整资产规模 | 最后同题没有先前的近期 1%–2% 波幅或凭空配置比例 |
| 中文日期被 URL 解析器吞进地址 | 产品与评分器共用 URL 提取函数，处理 Markdown 右括号、中文括号及编码路径 | 修复重复补来源和“未知链接”误判；同步重算全部基线，不增加模型调用 |

引用补全不是语义核查：已有一个实际来源链接时不自动堆叠所有检索结果，也不声称能识别每个论点是否有据。对完整语义蕴含和金融表述仍需要人工审核。

## 三、同题比较条件

- `mimo-v2.6-pro`，相同 16 条 smoke、相同合成输入及固定参考时间、相同 quick 模式、并发 2、每题一次。
- 模型自主选择工具；主数据集、必需/可选工具、数值期望及评分判定标准没有修改。
- 每次最大输出仍为 1600 Token，最大 4 步，单条 90 秒。改动的是提示词、工具说明/语义标注、quick 思考策略及引用后处理，不能把收益只归因于某一项。
- 原样保留所有模型轨迹；最后修正 URL 提取 bug 后，以同一评分器对首测和两轮优化记录重新评分。
- 工具使用固定资料，未调用实际 Tavily 或行情接口；测得的耗时不是生产实时数据服务 SLA。

复评分后，两端 dataset / fixture / evaluator 指纹一致，比较命令未报告汇总指标退化：

```powershell
python -m evals.runners.compare data/evals/model-smoke-2026-10-29/rescored-url-fix/report.json data/evals/model-optimized-final-2026-10-29/rescored-url-fix/report.json
```

## 五、迭代过程：没有只挑最好的一次

### 第一次优化复测

先完成 16 题真实复测，规则通过 14/16；P50 11.92 秒，121,454 Token。未通过项：知识库引用省略扩展名，以及有歧义的新闻故障题。

辅助审阅又发现安全拒绝题包含未经查询的“近期单日波动 1%–2%”。尽管规则通过，仍补充约束后，重新完整运行同一组 16 题，没有把局部新回答拼接成完整成绩。

### 最后一次完整复测与解析误判

原始报告为 13/16：两条正常 Markdown 链接后的中文日期，被旧提取器并入 URL，例如 `https://example.com/eval/fed)（2026-10-28）`，误报未知链接；同时导致产品重复补充引用附录。

增加括号/中文日期/百分号编码路径的回归测试，并将产品和评分器共用提取函数。用未改写的旧记录统一复评分后，最后结果为 15/16；首测仍是 7/16，第一版优化仍是 14/16。

没有修改模型回答、查询问题、持仓、工具结果或验收标准，也没有为了处理解析问题再请求模型。最后一轮原始轨迹保留了修复前重复附录的文本；产品最终解析补丁通过单测和离线工作流验证，未额外做第三轮完整付费复测。

### 唯一剩余基准未通过项

`failure-02` 的原问题是“新闻搜索失败时不要编造新闻”。模型将其视为规则确认，回复会诚实说明失败，但没有发起搜索，因此没有触发预期故障。两轮均保留未通过，不改分母、不强制模型做用户并未明确要求的搜索。

为验证真实故障处理，新增独立用例 [news_failure_explicit.jsonl](../evals/datasets/news_failure_explicit.jsonl)：

> 现在请检索最近72小时的黄金市场新闻；如果检索失败，请直接说明暂不可用，不能编造新闻或引用。

结果：**1/1 通过**。真实模型使用 2 次请求，实际工具返回预置失败，最终明确说明新闻检索暂不可用，没有虚构文章或引用。该专项结果单独记录，没有并入 16 题成绩，也不表示真实 Tavily 一定可用。

本轮共 62 次真实模型请求：第一版 30 + 最后版 30 + 故障专项 2；Token 共 251,917，费用需核对服务商账单。均为合成上下文，不使用用户真实持仓。

## 七、后续边界

先维持单 Agent，将完整新闻/知识证据与关键数值继续纳入语义审核，再做真实 full、多次采样和 quick/deep 配对比较。模型仍可能给出无充分依据的判断，提示词不是强制正确性证明；引用附录也不是事实核查模型。

生产行情/Tavily 可用性、中文向量检索质量、完整金融合规和多 Agent 架构收益仍未由本轮证明。不要为了提高评测分数牺牲用户明确要求，也不要为了增加技术名词提前拆成多个 Agent。
